# Asterism 정의서

## 한 문장 정의

**Asterism은 사용자의 로컬 폴더에 있는 여러 지식 자료를 보존·정리·열람하고, 읽을 수 있는 자료 사이의 관계를 성좌처럼 탐색하게 하는 Windows 앱이다.**

Markdown은 Asterism의 출발점이었고, Markdown·TXT 텍스트 자료는 현재 가장 깊게 지원된다. 그러나 제품의 기준 단위는 더 이상 특정 확장자 파일이 아니라 **자료(Resource)** 이다.

## 제품 원칙

### 로컬 우선

사용자의 자료는 사용자가 선택한 저장소 폴더에 일반 파일로 남는다. Asterism은 독점 포맷으로 원본을 가두지 않으며, 지원하지 않는 자료도 파일 자체를 훼손하지 않는다.

### 원본 보존

편집 가능한 자료는 원본 파일을 직접 저장한다. 보기 전용 자료는 앱 안에서 열람하되 원본을 수정하지 않는다. 외부 PDF를 가져오면 저장소에 복사본을 추가하며, 텍스트·콜아웃·하이라이터 주석은 PDF에 굽지 않고 별도 사이드카에 저장한다.

### 형식보다 능력

자료는 확장자 이름보다 가능한 행동으로 구분한다. 예를 들어 어떤 자료는 편집할 수 있고, 어떤 자료는 보기만 가능하며, 어떤 자료는 텍스트를 추출해 검색·관계 분석에 참여할 수 있다.

### 관계의 골격

성좌 지도는 가능한 모든 관계를 그리는 네트워크가 아니라, 사용자가 이해할 수 있는 관계의 골격을 보여주는 탐색 화면이다. 로컬 AI 제안은 관계 후보이며 사용자가 확정하기 전까지 원본 자료를 바꾸지 않는다.

## 핵심 용어

| 용어 | 정의 |
| --- | --- |
| **자료(Resource)** | 저장소 안에서 Asterism이 인식하는 파일 또는 읽기 전용 안내 문서. 이름·경로·형식·수정 시각과 형식별 능력을 가진다. |
| **노트(Note)** | 사용자가 직접 작성·편집하는 텍스트 자료. 현재 Markdown과 TXT가 해당한다. |
| **뷰어(Viewer)** | 원본을 바꾸지 않고 자료를 읽는 화면. PDF 리더는 비파괴 주석 레이어도 제공한다. |
| **편집기(Editor)** | 원본 파일을 수정하는 화면. Markdown 편집기가 첫 사례다. |
| **저장소(Vault)** | 사용자가 선택한 로컬 루트 폴더와 그 하위 자료의 집합. |
| **폴더(Folder)** | 자료를 정리하는 로컬 파일 시스템 계층. 탐색기에서 사용자 지정 순서를 가질 수 있다. |
| **링크(Link)** | 자료 사이를 명시적으로 잇는 관계. 현재 Markdown·TXT의 `[[자료 제목]]` 링크가 해당한다. |
| **관계(Relation)** | 링크·사용자 지정 연결·의미 분석 제안처럼 두 자료가 관련 있음을 나타내는 모든 정보. |
| **별(Star)** | 성좌 지도에서 표현되는 하나의 자료 노드. |
| **Asterism(별무리)** | 서로 가까운 관계를 가져 하나의 형상으로 읽히는 별들의 국소적 묶음. 향후 폴더·명시적 관계·의미 관계를 바탕으로 형성한다. 제품명 Asterism은 이 개념에서 왔다. |
| **Constella(지식 성좌)** | 여러 별과 별무리가 이루는 사용자의 전체 지식 관계망 및 이를 탐색하는 지도. |
| **발견된 관계** | 로컬 분석이 제안하지만 아직 원본에 확정 저장되지 않은 관계 후보. |
| **허수별** | 실제 자료를 나타내지 않는 배경용 별. 성좌 지도의 공간감만 돕는다. |

## 자료 형식과 능력

| 자료 형식 | 현재 상태 | 편집 | 앱 내 보기 | 검색·분석 | 성좌 참여 |
| --- | --- | --- | --- | --- | --- |
| `.md` | 지원 | 가능 | Markdown 렌더링 | 제목·본문 | 가능 |
| `.txt` | 지원 | 가능 | Markdown 호환 렌더링 | 제목·본문 | 가능 |
| `.pdf` | 지원 | 원본 편집 불가; 별도 주석 가능 | 페이지 렌더링·텍스트·콜아웃·하이라이터 | 파일명; 본문 추출 확장 예정 | 관계 메타데이터·본문 추출 기반으로 확장 예정 |
| 이미지 | 예정 | 불가 | 예정 | 메타데이터부터 검토 | 예정 |
| 기타 형식 | 검토 | 형식별 | 형식별 | 형식별 | 형식별 |

표의 ‘예정’은 제품 방향이며 이미 구현됐다는 뜻이 아니다. 새 형식은 아래 능력을 독립적으로 조합해 추가한다.

- 탐색기 표시와 파일명 검색
- 안전한 가져오기·이동·이름 변경·삭제
- 앱 내 뷰어
- 직접 편집기
- 텍스트 추출과 본문 검색
- 명시적 링크·관계 생성
- 로컬 의미 분석과 성좌 지도 참여

## 현재 사용 흐름

1. 사용자는 로컬 폴더를 저장소로 선택한다.
2. 탐색기에서 폴더와 자료를 원하는 순서로 정리한다.
3. Markdown·TXT 자료는 작성·미리보기·`[[자료 제목]]` 링크·성좌 탐색을 사용한다.
4. PDF는 `PDF＋` 또는 폴더 메뉴로 저장소에 가져오고, 탐색기에서 선택해 읽거나 비파괴 주석을 추가한다.
5. 보기 전용 자료도 원문을 바꾸지 않는 관계 메타데이터와 추출 텍스트를 통해 성좌에 참여한다. PDF는 그 기반을 단계적으로 추가한다.

## 확장 기준

새 자료 형식을 추가할 때는 개별 화면을 임시로 붙이기보다, 다음 질문에 답하는 자료 핸들러로 설계한다.

1. 저장소에서 어떤 파일을 자료로 인식하는가?
2. 원본을 직접 편집할 수 있는가, 아니면 보기 전용인가?
3. 앱 안에서 안전하고 충분하게 볼 수 있는가?
4. 텍스트나 메타데이터를 추출해 검색할 수 있는가?
5. 어떤 방식으로 다른 자료와 관계를 만들고 성좌에 참여하는가?

이 기준을 지키면 Asterism은 파일 형식이 늘어나도 같은 저장소·탐색기·관계 모델을 유지할 수 있다.
